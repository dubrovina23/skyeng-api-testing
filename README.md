# Skyeng API Testing — QA Portfolio Project

**Учебный проект по функциональному тестированию API личных событий в расписании Skyeng.**

> Статус: курсовая работа **зачтена** 17 ноября 2026 года. Репозиторий подготовлен как публичная демонстрация QA-навыков, а не как официальный проект Skyeng.

## О проекте

Проверялась функциональность получения расписания, создания личных событий и отображения сохранённых параметров через API. Тестирование включало позитивные и негативные сценарии, разработку тест-кейсов, создание коллекции запросов в Postman, автоматизацию проверок JavaScript и анализ результатов.

| Показатель | Результат |
| --- | --- |
| API-тест-кейсы | **15** (10 позитивных, 5 негативных) |
| Запросы в коллекции Postman | **26** |
| Автоматизированные проверки контрольного прогона | **94 из 94 пройдены**, 0 failed |
| Дефекты API | Новых критических дефектов в проверенном объёме не выявлено |
| Завершение тестирования | Тестовые события, отнесённые к этой работе, очищены (39 подтверждённых удалений) |

**Ограничение вывода:** успешные API-проверки не доказывают готовность всего продукта к релизу. Замечания, выявленные при UI-тестировании, рассматривались отдельно.

## Что я делала

- Проанализировала сценарии API и составила 15 тест-кейсов.
- Организовала запросы в папки позитивных и негативных проверок.
- Настроила `baseUrl`, локальную авторизацию через токен и передачу `eventId` между запросами.
- Написала JavaScript-проверки статуса ответа, структуры JSON, наличия ошибок и сохранённых параметров событий.
- Протестировала корректные и некорректные значения `title`, а также продолжительность событий, спецсимволы, описание и цвета.
- Запустила коллекцию в Postman Runner, проанализировала результаты и выполнила очистку созданных тестовых данных.

## Как посмотреть коллекцию

Импортируйте JSON из папки `postman/` в Postman. Сценарии и тестовые скрипты можно просмотреть **без запуска**. Для реального выполнения требуется собственная разрешённая учётная запись и локально настроенная авторизация. Подробности — в [инструкции](docs/setup.md).

> ⚠️ Запуск некоторых запросов **создаёт реальные личные события** в подключённой учётной записи. Не запускайте всю коллекцию случайно; убедитесь, что есть разрешение и план очистки.

Наставник отметил оформление тест-кейсов, актуализированный тест-план, сохранение ID события и проверки длительности в Postman. В качестве направлений развития рекомендовал расширить негативные проверки и добавить явные проверки HTTP-статусов во все негативные сценарии.
