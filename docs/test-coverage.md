# Покрытие тестирования

В курсовой подготовлены **15 API-тест-кейсов**. Поскольку один сценарий может включать создание события и отдельное получение расписания, в выгруженной коллекции **26 запросов**.

| № | Вид | Сценарий |
| --- | --- | --- |
| 01 | Позитивный | Получение расписания |
| 02 | Позитивный | Создание личного события |
| 03 | Негативный | Создание без обязательного поля `title` |
| 04 | Негативный | Создание с пустым `title` |
| 05 | Негативный | Создание с `title: null` |
| 06 | Негативный | Создание с числовым `title` |
| 07 | Негативный | Создание с логическим `title` |
| 08 | Позитивный | Событие длительностью 3 минуты |
| 09 | Позитивный | Событие длительностью 5 минут |
| 10 | Позитивный | Событие длительностью 1 час |
| 11 | Позитивный | Название со специальными символами |
| 12 | Позитивный | Пустое описание события |
| 13 | Позитивный | Длинное описание события |
| 14 | Позитивный | Изменённые цвета события |
| 15 | Позитивный | Название из одного символа |

## Автоматизированные проверки

В скриптах Postman используются `pm.test`, `pm.expect` и `pm.collectionVariables.set`.

Проверялись: HTTP-статусы там, где проверки добавлены; поля `data` и `errors` в ответах; структура массива `events`; наличие созданных событий; корректность длительности, названий, описаний и цветов.

**Примечание:** в экспортированной версии не все негативные запросы содержат явные проверки статус-кода. Это отражено как направление дальнейшего улучшения, без ретроспективного изменения результатов прогона.
